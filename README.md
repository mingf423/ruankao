## 学习计划与知识文档如何协作

1. **总计划负责路线**：24 周总计划说明阶段目标、时间分配和三科策略。
2. **周计划负责执行**：`00_学习计划与进度管理/W01.md` 至 `W24.md` 各自描述当周目标、每日安排、验收清单和复盘，不复制知识正文。
3. **知识文档负责沉淀**：知识原理按主题归入 `02_综合知识`，长期维护、持续补充；周计划通过相对超链接引用。
4. **案例与论文负责应用**：案例题归入 `03_案例分析`；项目叙事、架构决策和质量属性素材归入 `04_论文`。
5. **错题与模拟负责反馈**：错题归入 `05_错题与薄弱点`，整卷训练归入 `06_模拟考试`；复盘结论反向更新知识文档和后续周计划。
6. **一个主题一个主文档**：避免同一知识点在多个目录复制多份；其他文档只引用链接。

## 内容风格与结构规范

- 以中文为主，首次出现的重要术语可采用“中文（English）”。
- 先给结论，再解释定义、原理、适用条件、优缺点和架构权衡。
- 知识文档至少包含：考纲定位、核心概念、原理、适用场景、优势与局限、架构师视角、易混点、自测、参考来源。
- 案例文档采用：题目来源、考点定位、需求与约束、备选方案、决策理由、质量属性影响、得分点、个人复盘。
- 论文素材采用：项目背景与职责、架构问题、备选方案、架构决策、实施过程、质量属性效果、风险与不足。
- 所有时效性政策、标准、法规注明版本/日期、官方来源 URL 和核验日期；不确定内容标记“待核验”。
- 区分官方事实、教材知识、经验建议、模拟案例和个人判断；不编造真题、项目履历或效果指标。

## 多 Agent 内容生产约定

所有 Agent 在创建或修改文件前，必须阅读仓库根目录 [AGENTS.md](AGENTS.md)，并先搜索现有文档，优先补充已有主题，避免重复建档。

- 使用 UTF-8 Markdown；标题层级连续；目录索引使用 `README.md`。
- 文件名采用稳定中文主题名；周计划固定使用 `W01.md` 至 `W24.md`。
- 使用相对路径链接；新建文档后同步更新目录索引及相关周计划链接。
- 更新已有文档前先读取当前版本，保留已有有效内容。
- 重要文档注明来源、版本和更新记录；无法核验时明确说明。
- 模拟电商项目必须标注“模拟项目”，不得伪装成个人真实项目经历。
- 不要将学习计划、知识讲解、案例答案和论文素材混写在同一文档。

## 个人备考参数

- 目标：2027 年上半年系统架构设计师考试（具体考试安排以官方通知为准）。
- 基础：Java 中级开发经验约 4 年，了解部分架构。
- 时间：每周 10–15 小时，计划按 12 小时基准设计。
- 重点提升：综合知识覆盖、案例分析答题、论文结构与架构决策论证。
