# 2027 年上半年系统架构设计师备考计划

> 个人画像：Java 中级开发，4 年开发经验，了解部分架构；目标参加 2027 年上半年系统架构设计师考试；每周可投入 10–15 小时；当前薄弱项为综合知识、案例分析、论文写作。
>
> 计划周期：2026-11-23 至 2027-05-09，共 24 周。2027 年上半年具体考试日期、批次及报名安排以中国计算机技术与软件专业技术资格网发布的正式通知为准。本计划按 24 周倒排，若官方考试日期变化，应整体平移或压缩冲刺阶段。

## 1. 备考目标与策略

### 1.1 核心目标

- **综合知识**：覆盖官方考试大纲要求，形成知识地图，持续提升选择题正确率。
- **案例分析**：掌握需求识别、约束分析、方案比较、架构决策和质量属性论证。
- **论文写作**：把真实项目经验转化为结构完整、论证可信、体现架构决策的论文。
- **工程能力**：从 Java 功能开发视角提升到系统级架构设计、权衡与评估视角。

> 知识地图入口：[官方大纲知识概览图索引](./01_官方大纲与考试政策/脑图索引.md)。先用体系总图确认每个主题落在哪一层，再进入对应的综合知识、案例分析与论文概览图；每周的具体入口见 [W01–W24 文档](./00_学习计划与进度管理/README.md)。

### 1.2 个人优势与风险

| 维度 | 当前情况 | 备考策略 |
|---|---|---|

### 1.3 每周时间分配

以每周 12 小时为基准，可在 10–15 小时范围内弹性调整。

| 模块 | 每周时间 | 占比 | 主要任务 |
|---|---:|---:|---|
| 综合知识 | 4 小时 | 约 33% | 教材学习、知识图谱、选择题、错题 |
| 案例分析 | 4 小时 | 约 33% | 案例拆解、限时答题、答案复盘 |

## 4. 每日学习方法

### 周一：知识输入（90 分钟）

1. 先浏览本章目录和考试大纲对应要求。
2. 精读教材核心概念与原理。
3. 绘制知识结构图，标出易混淆概念。
4. 记录仍不理解的问题。

### 周二：案例输出（120 分钟）

1. 限时阅读题干，圈出业务目标、约束和质量属性。
2. 独立作答，不先看答案。
3. 对照参考答案，标出遗漏的得分点。
4. 将错误归类为概念错误、审题错误、方案不完整或表达不准确。

### 周三：综合知识强化（90 分钟）

1. 完成当周专题选择题。
2. 记录错题对应的考纲知识点。
3. 回到教材或可信资料补齐原理。
4. 对错题进行间隔复习。

### 周四：论文输出（120 分钟）

1. 阅读论文题目并拆解关键词。
2. 明确项目背景、本人职责和核心架构问题。
3. 写提纲或一个 300–500 字正文段落。
4. 检查技术决策是否有原因、过程和效果支撑。

### 周五：回顾（60 分钟）

1. 复习本周错题。
2. 回顾标准规范与易混淆概念。
3. 阅读一小段专业英语材料。
4. 确认周末训练目标。

### 周六：集中训练（180 分钟）

- 60 分钟：综合知识专题或限时刷题。
- 60 分钟：案例题独立作答与复盘。
- 60 分钟：论文素材、架构图或模拟项目设计。

### 周日：复盘（60 分钟）

回答并记录：
- 本周真正掌握了什么？
- 哪些题目仍然不会，原因是什么？
- 哪些知识点需要下周回补？
- 下周三科各自最重要的一个目标是什么？

## 5. 三科专项训练标准

### 5.1 综合知识

每周建议完成 100–150 道题（基础诊断周可适当减少），并精读 2–3 个重点专题。

错题表建议字段：

| 字段 | 记录内容 |
|---|---|
| 日期/题目来源 | 真题年份、章节或模拟题 |
| 考纲知识点 | 对应官方大纲条目 |
| 错误原因 | 概念混淆、记忆不牢、计算错误、审题失误 |
| 正确理解 | 用自己的话解释原理 |
| 复习状态 | 待复习、已复习、已掌握 |

阶段性训练目标（仅为个人训练目标，不是官方合格线）：
- 第 1 个月：基础题正确率争取达到 55%–60%。
- 第 3 个月：专题题正确率争取达到 65%–70%。
- 第 5 个月：模拟正确率争取稳定在 75% 左右。
- 考前：通过多套模拟检验稳定性，重点分析错题而非只看分数。

### 5.2 案例分析

采用“五步答题法”：
1. **识别需求**：系统要达到什么业务目标和质量属性？
2. **识别约束**：现有系统、技术、预算、组织和运行环境有哪些限制？
3. **分析方案**：有哪些可选架构或技术方案？
4. **给出决策**：选择哪种方案，理由和适用条件是什么？
5. **论证效果**：如何改善性能、可用性、安全性、可维护性等，是否引入新的权衡？

每周至少完成 2 道案例题；每月完成一次完整限时案例训练。

分布式事务专题应比较 2PC、TCC、Saga、本地消息表、事务消息等方案的原理、适用场景、复杂度、性能和故障恢复机制，不应只背定义。

### 5.3 论文写作

论文四段式训练框架：

1. **项目背景**：业务背景、规模、建设目标、本人职责和项目约束。
2. **架构设计**：总体架构、架构风格、关键技术选型及其理由。
3. **核心实践**：关键问题、备选方案、决策过程、实施措施和质量属性权衡。
4. **实施效果与总结**：用可核验指标或事实说明效果，指出不足和改进方向。

建议建立论文素材库：

| 方向 | 素材重点 |
|---|---|
| 微服务架构 | 服务拆分、服务治理、边界与依赖 |
| 高可用架构 | 冗余、故障转移、限流、降级、容灾 |
| 分布式架构 | 一致性、分布式事务、幂等与补偿 |
| 云原生架构 | 容器、编排、弹性伸缩、可观测性 |
| 架构评估 | 质量属性场景、风险点、权衡点 |
| 信息安全架构 | 身份认证、访问控制、加密、审计与合规 |

论文练习必须基于真实参与经历；若使用模拟项目，应明确是模拟案例，不虚构个人履历、项目规模或效果数据。

## 6. 贯穿备考的模拟项目

### 项目：大型电商平台架构升级（模拟项目）

**背景问题**
- 高并发场景下响应变慢。
- 订单、库存、支付模块耦合。
- 数据库读写压力大。
- 业务高峰期存在可用性风险。
- 扩容和跨服务数据一致性困难。

**待设计能力**
- 需求分析与架构约束识别。
- 单体、分层、SOA、微服务等架构风格的适用性比较。
- 服务边界、API 网关、服务治理与配置管理。
- MySQL、Redis、消息队列的数据与缓存策略。
- 分布式事务、幂等、重试、补偿和最终一致性。
- 限流、熔断、降级、隔离、容灾与容量规划。
- 身份认证、授权、数据保护和审计。
- 日志、指标、链路追踪与架构评估。

**Java 技术经验映射**

| 已接触技术 | 应提升的架构能力 |
|---|---|
| Spring Boot | 分层架构、服务边界与组件设计 |
| Spring Cloud | 服务治理、发现、配置与容错 |
| MySQL | 数据建模、事务、索引、读写分离与分片权衡 |
| Redis | 缓存一致性、穿透/击穿/雪崩治理 |
| Kafka/RocketMQ | 消息可靠性、幂等、顺序与最终一致性 |
| Nginx | 负载均衡、反向代理与高可用入口 |
| Docker/Kubernetes | 容器化部署、编排与弹性伸缩 |
| JVM | 内存、线程、垃圾回收与性能诊断 |

**项目阶段交付物**

| 时间 | 交付物 |
|---|---|
| 第 1 个月 | 需求分析、约束清单、总体架构草图 |
| 第 2 个月 | 架构风格比较、架构视图、质量属性场景 |
| 第 3 个月 | 微服务拆分、数据架构与分布式方案 |
| 第 4 个月 | 安全、性能、可靠性和容灾设计 |
| 第 5 个月 | 架构评估报告、论文初稿 |
| 第 6 个月 | 完整架构设计文档与模拟答辩复盘 |

资料使用原则：
1. 先对照当前有效考试大纲建立知识清单。
2. 教材用于系统学习，历年真题用于理解命题方式。
3. 第三方题解需交叉核验，不能把未经核实的答案当作标准答案。
4. 关注官方考试通知、报名时间、考试批次和机考要求。

## 10. 长期复盘与调整规则

- 连续两周综合知识正确率无提升：减少泛读，改为按错题对应知识点回教材。
- 案例题答案“知道但写不出”：增加限时闭卷作答，并按得分点拆解答案。
- 论文只有技术名词、缺少决策论证：补充备选方案、约束、取舍、实施过程和效果证据。
- 工作繁忙导致计划中断：优先保留三科最小训练量，不用熬夜补进度；下一周重新安排。
- 官方考试日期与本计划冲突：以官方日期为准，优先保留真题模拟、论文限时训练和薄弱点回补。

---

**执行原则：每周有输入、有输出、有复盘；三科同步推进；以官方大纲为边界，以架构设计能力提升为长期目标。**
