# 单机订单系统性能优化（教学案例）

> **题目类型**：教学用简化案例（非真实考题原文）  
> **适用阶段**：W01 及入门阶段，帮助熟悉案例分析题型与五步答题法  
> **核心考点**：性能瓶颈识别、硬件/架构约束、方案比较、质量属性权衡

## 题目

某公司现有订单处理系统采用单机部署，随着业务增长，高峰期订单处理出现明显延迟，数据库服务器 CPU 和磁盘 I/O 持续高位。公司希望在尽量控制成本的前提下提升系统处理能力，并保证高峰期核心下单功能可用。请完成以下问题：

1. 分析当前系统主要面临的性能瓶颈可能有哪些？
2. 给出两种可行的改进架构思路，并比较其优缺点。
3. 你推荐哪种思路作为优先实施方案？请说明理由，并简述该方案对系统性能和可用性的影响。

---

## 参考范文（优秀答法示范）

### 1. 主要性能瓶颈分析

从题干可知，系统单机部署，高峰期订单处理延迟，且数据库服务器 CPU 与磁盘 I/O 持续高位。可能的主要瓶颈包括：

- **计算瓶颈**：单机 CPU 能力有限，订单处理逻辑（校验、库存扣减、写库）在高峰并发下成为热点。
- **存储 I/O 瓶颈**：磁盘 I/O 高位说明随机写或读压力大，可能与订单频繁写入、缺少合适缓存或索引不当有关。
- **架构瓶颈**：单机部署导致无法水平扩展，所有请求集中在一台机器，缺乏分流与隔离。

这些瓶颈共同导致响应时间上升，并可能在更高并发下引发雪崩。

### 2. 两种可行改进思路比较

| 方案 | 核心做法 | 优点 | 缺点 |
|------|----------|------|------|
| 方案A：垂直扩展 + 缓存 | 升级数据库服务器配置，引入 Redis 缓存热点数据（商品、库存），优化慢 SQL | 改动相对小，上线快，对现有代码侵入低 | 仍受单机上限限制，成本随配置上升较快，无法根本解决扩展问题 |
| 方案B：应用与数据适当分离 + 读写分离 | 将应用层与数据库分离部署，数据库做主从复制，读请求分流到从库，写仍走主库；核心下单链路增加限流与降级 | 具备一定水平扩展能力，读写压力分离，可用性更好 | 改造量较大，需处理复制延迟与一致性问题，运维复杂度上升 |

### 3. 推荐方案与理由

在“尽量控制成本”和“保证高峰期核心下单可用”的约束下，建议**优先实施方案A，并同步做有限的读写分离准备**。

理由：
- 方案A能较快降低当前 CPU 与 I/O 压力（缓存命中可显著减少数据库访问），符合成本与时间约束。
- 垂直扩展 + 缓存对现有架构冲击小，风险可控。
- 同时保留向方案B演进的空间（先把读写路径理顺）。

对质量属性的影响：
- **性能**：缓存降低平均访问时间，峰值响应时间有望明显改善。
- **可用性**：限流与降级可保护核心下单功能，避免整系统被拖垮；但单机仍是单点，长期需向多实例演进。
- **代价**：引入缓存后需关注一致性（库存等热点数据的更新策略），这是新的设计点。

## 五步答题法对照

1. **识别需求**：提升处理能力，保证高峰期核心下单可用。
2. **识别约束**：控制成本、现有单机架构、时间与改造风险。
3. **比较备选方案**：方案A（垂直+缓存）与方案B（分离+读写分离）。
4. **给出决策及理由**：优先 A，兼顾成本与见效速度，同时为 B 留接口。
5. **论证质量属性效果**：性能改善、可用性保护、新增一致性权衡。
