# 架构风格与模式

## 核心知识框架
分层、客户端/服务器、管道-过滤器、仓库、事件驱动、微内核、面向服务等风格；组件、连接件、约束和架构视图；架构模式与设计模式的层次差异。

## 典型风格比较
| 风格 | 优势 | 局限/风险 | 常见场景 |
|---|---|---|---|
| 分层 | 职责清晰、便于维护 | 跨层调用与性能开销 | 业务层次明确的系统 |
| 事件驱动 | 解耦、异步扩展 | 一致性与追踪复杂 | 异步集成、高吞吐 |
| 微服务 | 独立部署、自治演进 | 分布式复杂度高 | 业务边界与团队成熟 |

## 架构师视角
不能脱离需求宣称某种风格最好，应以质量属性场景、组织能力和技术约束作出权衡。

## 易混点与自测
架构风格/设计模式；组件/连接件；事件驱动/消息队列实现。
